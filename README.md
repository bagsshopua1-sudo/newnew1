# Lighter DOM-Bot — ETH/BTC, торговля по стакану

Бот читает L2-стакан (order book) биржи Lighter (zero-fee perp DEX), ловит
крупные лимитки ("стенки") и торгует их поглощение/пробой лимитными ордерами,
с автоматическим стоп-лоссом, частичным тейк-профитом и трейлингом остатка.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
```

Открой `.env` и настрой параметры под себя (см. комментарии в файле).

## Шаг 1 — мониторинг 1 час (обязательно перед любой торговлей)

```
MODE=collect
COLLECT_MINUTES=60
```

```bash
python bot.py
```

Ничего не торгует, только пишет в `logs/collect_*.csv` и `logs/walls_*.csv`
реальное поведение стакана ETH и BTC на Lighter: как часто появляются стенки
от `WALL_MIN_USD`, насколько они крупные, какой обычно имбаланс bid/ask.
По итогу в консоли — сводка. Если час покажет, что реальных стенок мало или
пороги не совпадают с рынком — поправь `WALL_MIN_USD` / `IMBALANCE_THRESHOLD`
в `.env` и прогони ещё раз (час можно увеличить через `COLLECT_MINUTES`, как
и договаривались — сейчас стоит именно час).

## Шаг 2 — paper-режим (виртуальные сделки на реальном стакане)

```
MODE=paper
```

```bash
python bot.py
```

Бот полностью работает: сигналы → вход лимитками с перестановкой (chase) →
стоп-лосс/тейк-профит/трейлинг — но через встроенный в SDK `PaperClient`,
то есть без реальных денег. Смотри логи в консоли, накапливай статистику
минимум несколько дней/недель, прежде чем переходить дальше.

## Шаг 3 — live (реальные деньги)

```
MODE=live
ACCOUNT_INDEX=<твой account index на Lighter>
API_PRIVATE_KEY=<приватный ключ API-ключа, НЕ ключ кошелька>
```

Заводи туда только ту сумму, которую готов потерять целиком — это прямо
следует из механики рынка: ни один бот не гарантирует прибыль, стоп-лосс
ограничивает убыток на сделку, но не убирает риск полностью (гэпы,
проскальзывание на тонком стакане, сбои сети).

## Веб-дашборд (статус-страница)

В режимах `paper` и `live` вместе с ботом поднимается веб-сервер:
`http://<host>:<DASHBOARD_PORT>` (по умолчанию порт 8080; на Render/Railway
платформа сама подставляет `PORT` — бот его подхватит автоматически).

На странице: депозит/PnL, открытые позиции, история сделок, лог событий в
реальном времени (обновляется раз в 3 секунды), и кнопка **аварийной
остановки** — закрывает все позиции и блокирует новые входы одним кликом.
Это и есть тот "сайт", через который следишь за ботом, не заходя на ПК.

## Бэктест на собранных данных

После `MODE=collect` в `logs/` появятся `collect_<symbol>_*.csv` и
`walls_<symbol>_*.csv`. Прогони их через тот же движок сигналов:

```bash
python backtest.py logs/collect_ETH-USDC_20260817_120000.csv logs/walls_ETH-USDC_20260817_120000.csv ETH-USDC
```

Покажет число сделок, win-rate, средний выигрыш/проигрыш и просадку.
Это упрощённая модель (без чейзинга лимитки и без трейлинга остатка) — для
грубой оценки логики сигналов, не для точного прогноза прибыли.

## Kill switch (аварийная остановка)

Закрывает все открытые позиции reduce-only ордерами, отменяет все активные
ордера и блокирует новые входы. Срабатывает:
  - **вручную** — кнопкой на дашборде;
  - **автоматически** — при пробитии дневного лимита убытка (`DAILY_LOSS_LIMIT_PCT`),
    при серии убытков подряд (`MAX_CONSECUTIVE_LOSSES`), или при затяжном
    обрыве связи со стаканом (5+ неудачных переподключений подряд).

После срабатывания бот и дашборд продолжают работать (чтобы было видно, что
произошло), но новых сделок не будет, пока не нажмёшь "Возобновить торговлю"
на дашборде.

## Трендовый / волатильностный фильтр

Сигналы "абсорбция" (фейд/контр-тренд) не выставляются против сильного
тренда (по кресту двух EMA на mid-цене) — так бот не пытается ловить
разворот в разгар сильного движения. Отдельно: при аномальном всплеске
волатильности (резкий скачок отклонения цены относительно обычного уровня)
генерация новых сигналов на время приостанавливается — такие моменты
(ликвидации, новостные свечи) стакан ведёт себя не по обычной логике стенок.

## Журнал сделок

Каждая сделка (вход/выход, PnL, причина закрытия) пишется в SQLite
`logs/trades.db`. Дашборд читает историю и статистику оттуда же. Можно
открыть файл любым SQLite-браузером для своего анализа.

## Как устроена логика ("мозг")

- **Вход**: лимитным ордером у стенки/на тач-цене, post-only (без тейкер-комиссии
  и без слippage маркета). Если не исполнилась за `ORDER_FILL_TIMEOUT_SEC` —
  бот отменяет и переставляет её вслед за рынком, до `MAX_REPRICE_ATTEMPTS` раз.
  Не исполнилась совсем — сигнал пропускается, бот не гонится за ценой маркетом.
- **Стоп-лосс**: выставляется на бирже сразу после входа (нативный reduce-only
  ордер) на весь объём — минус всегда ограничен `STOP_LOSS_PCT`.
- **Тейк-профит**: частичный (`TAKE_PROFIT_1_SIZE` от объёма) на `TAKE_PROFIT_1_PCT`.
  После срабатывания остаток переводится на трейлинг-стоп (`TRAILING_STOP_PCT`),
  который подтягивается за ценой, но никогда не отодвигается назад — так плюс
  может дорасти, а не фиксируется вслепую по одной цели.
- **Риск на сделку**: `RISK_PER_TRADE_PCT` от депозита, размер позиции считается
  от дистанции до стопа (а не наугад), плечо ограничено `MAX_LEVERAGE`.
- **Circuit breaker**: дневной лимит убытка `DAILY_LOSS_LIMIT_PCT` и пауза
  `COOLDOWN_MINUTES` после `MAX_CONSECUTIVE_LOSSES` подряд убыточных сделок —
  бот сам останавливается, а не пытается отыграться.

## Важные честные оговорки

- Это рабочий каркас, а не готовая гарантированно прибыльная система. Логику
  стенок/абсорбции/пробоя нужно откалибровать под реальные данные (шаг 1-2)
  под именно те инструменты и объёмы, которыми ты торгуешь.
- Код написан и проверен через интроспекцию реального `lighter-sdk` (реальные
  сигнатуры методов), но живой прогон против биржи не выполнялся из песочницы
  (нет сетевого доступа к домену Lighter из этой среды) — обязательно
  протестируй сначала `MODE=collect`, затем `MODE=paper` на своей машине,
  прежде чем включать `MODE=live`.
- На Lighter (как и на dYdX) стакан у некоторых пар тоньше, чем на топовых
  CEX — поэтому вход только лимитками и без агрессивного "догона" маркетом.
- Держи в боте только те деньги, потерю которых готов принять целиком.

## Структура проекта

```
config.py          - загрузка .env
exchange_client.py - обёртка над lighter-sdk (ордера, позиции, рынки)
market_data.py      - подписка на стакан по WebSocket, детект стенок/имбаланса
trend_filter.py       - EMA-тренд и детектор всплеска волатильности
signals.py             - сигнальный движок (absorption / breakout)
risk.py                 - размер позиции, стоп/тейк, дневной лимит, circuit breaker
kill_switch.py           - аварийная остановка (ручная + автоматическая)
trade_log.py              - SQLite-журнал сделок
order_manager.py           - вход с chase, SL/TP, трейлинг остатка, flatten_all
dashboard.py                 - веб-дашборд статуса (aiohttp)
collector.py                  - режим MODE=collect (часовой мониторинг)
backtest.py                    - прогон стратегии на собранных CSV
bot.py                          - точка входа, связывает всё вместе
```
